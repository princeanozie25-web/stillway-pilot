# For Codex: prove v0.3 wrong without my code

Three claims, in order of how little you need to trust. Do not import `stillway3/certify.py`, `stillway3/check_tables.py` or `v03/eval_edits.py`. The world is the Dispatch-3 of `docs/v02_codex_challenge.md` section 1, with any number of legs; the exact planner is unchanged.

## Claim 1. These integer tables are a correct planner for every job length

Input: one JSON file, `results/v03/cert/v3r24fix_s1_tables.json` (also `v3r24fix_s2`, `_s4`, `_s5`, `v3r24fixl_s3`, `v3r24fixr_s3`, and the outcome-trained `results/v03/cert_o/v3o_s1_tables.json`).

| Table | Shape | Meaning |
|---|---|---|
| `term[q0][q1]` | 4 × 4 | code at the start of the backward sweep. `q` = gate requirement: 0 none, 1 must be closed, 2 must be open (3 = never written; unused) |
| `cell[code][leg]` | 64 × 64 | code after one more leg, going backwards |
| `route[code][leg][gates]` | 64 × 64 × 4 | route proposed at the current leg: 0 = first route, 1 = second |
| `deliver[parcel][closed + 1]` | 4 × 4 | dock for a parcel whose order says dock `parcel`, when dock `closed` is shut (−1 = none) |

Encodings: a trip is `effect * 2 + gate`, effects 0 keep, 1 toggle, 2 open (set to 1), 3 close (set to 0). A leg kind is `trip_of_route_0 * 8 + trip_of_route_1`. `gates = gate0 * 2 + gate1`.

How the tables plan a route at leg `i` of a job with legs `0..L-1`:

```
code = term[q0][q1]
for j = L-1 down to i+1:  code = cell[code][leg_j]
route = route[code][leg_i][gates]
```

Claim: for every `L >= 1`, every sequence of leg kinds, every `(q0, q1)` in 0..2, every gate state, the route is one of the exact planner's valid routes; and `deliver` equals the exact planner's dock on all 12 entries with `parcel` in 0..2.

Ways to attack it:
- Brute force short jobs against your own planner (all jobs of up to 2 legs is 150,000 checks; up to 3 legs over all 64 leg kinds is 9.4 million).
- Random long jobs (100 legs is fine; the tables are cheap).
- Rebuild the closure argument yourself (`docs/v03_certificate_scope.md`), or find a hole in it.

For contrast, `results/v03/cert/v3r24_s1_tables.json` (before repair) should fail: I count 960 wrong entries, and `results/v03/cert/v3r24_s1.json` lists 20 failing jobs.

## Claim 2. The network computes those tables

Input: `runs/v3r24fix_s1/checkpoint.pt`, a `torch.save` of `{"cfg", "state", "extra"}`. Modules in `state` (all MLPs are Linear-ReLU-Linear-ReLU-Linear, width 128):

- `emb_req`, `emb_par`: embeddings of a register value (index 3 = never written), size 16.
- `term`: input `[emb_req(q0), emb_req(q1)]` (32) → 16. Then `tanh`, then the nearest row of `codebook` (64 × 16, squared distance): that row's index is the code, and the row is the carry.
- `cell`: input `[carry (16), leg (10)]` → 16, `tanh`, nearest code. A leg is `[one-hot effect of route 0 (4), gate of route 0, one-hot effect of route 1 (4), gate of route 1]`.
- `route`: input `[carry (16), current leg (10), gate0, gate1]` → 2 logits; argmax.
- `deliver`: input `[emb_par(parcel register) (16), one-hot closed dock: none, 0, 1, 2 (4)]` → 3 logits; argmax.

Claim: evaluating these modules on every input reproduces the tables file exactly.
