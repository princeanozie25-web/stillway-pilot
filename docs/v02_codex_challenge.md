# For Codex: replay a correction and score it without my evaluator

Everything below is enough to rebuild the Dispatch-3 scorer and replay an edit. Do not import `stillway2/edits.py` or `v02/m3_eval.py`. You may use `stillway2/model3.py` for the network forward pass, or rebuild it from section 3.

## 1. The world (rebuild this)

A job has `L` legs (2 to 4). Leg `i` has two routes; each route has a trip `(effect, gate)`. Effects on the named gate: K keep, T toggle, O set to 1 (open), C set to 0 (closed). Two gates, each 0 or 1. Station `i` (after leg `i`) may have a parcel.

Work order, six fields: `gate0`, `gate1` in {0 none, 1 must be closed, 2 must be open}; `parcel1..parcel4` in {0, 1, 2} = dock.

Frame of slots, in order: `INIT`; then for each leg `i` = 0..3: `K` wait slots, a `ROUTE` slot, a `DELIVER` slot (`K` = 1 in all v0.2 runs). A job takes part in a slot when: INIT always; WAIT `i` if leg `i` exists and that wait is switched on for the job; ROUTE `i` if leg `i` exists; DELIVER `i` if leg `i` exists and station `i` has a parcel. Slots a job does not take part in are skipped: no observation, no memory update.

Exact planner:

- ROUTE `i`: for each route, enumerate every choice of routes on the remaining legs and take the largest number of gate requirements met at the end. Valid routes are those that reach the overall largest number.
- DELIVER `i`: the order's dock for that parcel, or `(dock + 1) mod 3` if that dock is the closed one.

Reference implementation in plain Python, 20 lines: `ref_valid_routes` and `ref_dock` at the bottom of `stillway2/world3.py`.

## 2. The observation (92 numbers)

| Index | Content |
|---|---|
| 0–3 | slot kind one-hot: INIT, WAIT, ROUTE, DELIVER |
| 4–7 | leg index one-hot: this slot's leg for ROUTE and DELIVER; the number of legs already travelled (capped at 3) otherwise |
| 8–9 | gate states |
| 10–13 | closed dock one-hot: none, 0, 1, 2 |
| 14–15 | decoration bits (no effect) |
| 16–39 | message, 4 numbers per field in the order gate0, gate1, parcel1..4: `[shown, value==0, value==1, value==2]`. At INIT all six fields are shown. |
| 40–91 | four legs × 13: `[exists, already travelled, has parcel, L effect one-hot K T O C, L gate, R effect one-hot, R gate]`. For a leg that does not exist all 13 are 0. |

## 3. The network (if you rebuild it)

`runs/<core>/checkpoint.pt` is a `torch.save` of `{"cfg", "state", "extra"}`. With `W = 128`, 8 slots, 16 codes, code size 16:

1. `mem` = the 8 code vectors `codebook[slot][id]` joined (a slot with ID −1 is zeros). `h = tanh(mem_in(mem))`.
2. `g` = observation[0:40]. `xg = enc_g(g)`. `h = GRU(xg, h)`.
3. For leg `i` = 3, 2, 1, 0: if the leg exists and is not yet travelled, `h = GRU(enc_leg([g, leg_i]), h)`.
4. `h = GRU(xg, h)`.
5. Action logits `head(h)`: indices 0–1 routes L, R; 2–4 docks. Take the argmax inside the slot's kind.
6. New memory vectors = old memory vectors + `to_slots(h)`; each slot goes to the nearest code (squared distance) in its own codebook. Those 8 IDs are the saved state. A job that skips a slot keeps its IDs.

## 4. The edit under test

`runs/<core>/editors.pt` holds `slot_table` (6 × 3 integers) and `slot_known` (6 × 16 booleans).

Slot write, for field `f` (0..5) and new value `v` (0..2): if the current code in slot `f` is −1, or `slot_known[f][code]` is false, or `slot_table[f][v]` is −1, **abstain**. Otherwise set slot `f` to `slot_table[f][v]`. Nothing else changes. The planner then resumes with no message.

## 5. Scoring one attempt

Run the job with plain memory to the pause slot. Apply the correction to the true order. Apply the method. Resume to the end.

- Eligible: the field still matters at the pause (a gate field up to the last ROUTE slot; a parcel field up to its DELIVER slot); under the corrected order all gate requirements can still be met together from the world state at the pause; and the same job with the correction ignored fails.
- Edited obligation met: the edited gate ends in the required state, or the edited parcel went to the right dock.
- Unrelated obligations met: every other gate requirement and every other parcel.
- Joint success: both, and the editor did not abstain.

## 6. What to check against

- `results/v02/m3/<core>_final_items.json`: per attempt, for every method: eligible, joint, abstained, edited_ok, unrelated_ok, field, legs.
- `results/v02/traces/<core>.json` (from `v02/export_trace.py`): complete step-by-step traces of a few attempts: every observation vector, the IDs before and after each step, the action, the edit, and the final gates and docks. Rebuild these first.
- The final jobs are regenerated by `python v02/m3_eval.py runs/<core> final $(python v02/final_seed.py)`.

## 7. A challenge that I have not seen

The final strata were authored by the same assistant that built the model. To test what I could not: write your own generator or your own fixtures. Suggested axes I did not include: five legs; three gates mapped onto the two inputs is not possible, so instead a leg whose two routes are the same trip; two stations sharing one parcel destination rule; wait counts above one per leg; edits to two fields at the same slot. `v02/run_fixture.py` runs a job given as JSON (layout, gates, order, waits, edit) through the frozen core and editor and prints the outcome, so your scorer can be compared item by item.
